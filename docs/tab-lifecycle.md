## Tab lifecycle

Use these methods in `js`, awaiting every call. Start with `await browser.nameSession('🔎 Research')`, then `let tab = await browser.tabs.new(url)`. Agent-created tabs open in a named Chrome group, in the background, muted until the user looks at them.

To use an existing tab, call `await browser.user.openTabs({query:'…',limit:20})`, then `let tab = await browser.user.claimTab({tabId})`. Read the returned `items` array. Discovery reports its `scope:"unclaimed"`, visible/in-scope totals, excluded owned/unsupported counts, and match count. Matching is a trimmed, case-insensitive literal substring of URL OR title (no token splitting). Results are recency-sorted with tabId as a tie-breaker, default to 20 and allow up to 100 per page. Continue with `offset: nextOffset` while `hasMore`; each request is a fresh snapshot, so tab changes can shift pagination. Discovery never claims or loads a tab. To claim the foreground tab, use `{active:true}`. Unique URL/title lookup is also supported; `expectedUrl` and `expectedTitle` check exact identity when necessary. Claiming alone does not observe the page. Claimed user tabs stay outside the agent group and are never closed by finalize.

`await browser.tabs.list()` returns controlled tabs with string `id`, numeric backend `tabId`, `origin` and `state`. Obtain a handle with `await browser.tabs.get(id)`. The page id is stable across navigation and becomes stale after logical closure. In Electron it also survives WebContents replacement; `lifecycle` reports dormant, loading or ready. A newly attaching extension tab may return `pending:true` without an id; match its numeric `tabId` on a later list call. Unknown ids are rejected rather than adopted.

`await tab.release()` keeps the tab open and gives up control; an agent-created tab leaves only its temporary session group and is unmuted unless its mute state is native (a raw-created tab or an explicit `tabs.update({muted})` call). User-arranged groups are preserved. `await tab.close()` closes a controlled tab. For bulk user-tab cleanup, use `await browser.user.closeTabs([tabId1,tabId2])` without claiming; its result reports `closed` and `failed` ids. Keep discovery and planning in REPL variables, and return a summary before the next decision. Do not move every row into the conversation.

Prefer `await tab.markDeliverable()` to preserve a result, `await tab.markHandoff()` to retain control for a later turn, and `await tab.clearRetention()` to remove a mark. Marks belong to the logical tab and do not require a loaded page. Finish with the MCP tool `session_finalize`, or `await browser.tabs.finalize({keep:[{tab,status:'deliverable'}]})` in `js`. Explicit keep entries override stored marks and require the complete `tab.id` or a Tab handle in JavaScript, never a variable name or numeric `tabId`. Invalid keep entries abort before any cleanup. `deliverable` tabs leave temporary session groups and stay open; explicitly arranged groups are preserved; `handoff` tabs stay grouped for a later turn; other agent tabs close. Failed tabs retain their lease for retry. After successful finalize, old handles are released; obtain fresh handles in a later turn. Let running JavaScript finish before calling the separate finalize tool.

Resetting JavaScript leaves browser tabs open. Closing the MCP client closes its local IPC connection and finalizes only that connection’s session. A host restart creates a new session; `session_restarted` means rebuild REPL bindings and inspect the browser before continuing. An idle browser session is finalized after an hour.

For grouping, renaming, moving, pinning and window organization, use `browser.chrome.call` without claiming tabs. Read `capabilities/chrome` for the task-to-method map and complete group workflow. Grouping does not automatically keep agent-created tabs.
